# 🎮 7team 2인 협동 미로 탈출

> **최종 수정일:** 2026-11-06  
> **작성 팀:** 7team  

---

## 📌 1. 프로젝트 개요

두 명이 한 방에서 서로 다른 출발점에서 시작해 장애물을 피하고 코인을 모은 뒤, **두 명 모두 종점에 도착하면 클리어**하는 2인 협동 미로 탈출 게임입니다.  
한 명이라도 사망하면 둘 다 처음부터 다시 시작합니다.

| 항목 | 내용 |
| :--- | :--- |
| **장르** | 2인 협동 미로 탈출 |
| **인원** | 방 하나당 정확히 2명 |
| **조작** | `WASD` 이동 |
| **클리어 조건** | 두 명 모두 종점 도착 |
| **실패 처리** | 한 명이라도 사망하면 두 명 모두 새 랜덤 출발점에서 재시작, 코인 다시 배치 |
| **점수** | 클리어한 시도에서 모은 코인 점수 (팀 점수 = 두 명 합) |
| **랭킹** | 스테이지별, 팀(한 판) 단위 |
| **판정** | 모든 이동·충돌·획획득·클리어는 **서버가 판정**, 클라이언트는 입력만 보냄 |

## 🔄 2. 한 판의 흐름

1. **닉네임 설정**: 접속 후 닉네임을 정합니다 (이번 접속에만 쓰는 1회성).
2. **방 생성 및 입장**: 한 명이 방을 만들면 입장 코드가 나오고, 다른 한 명이 그 코드로 들어옵니다.
3. **게임 시작**: 두 명이 모이면 서버가 스테이지를 시작하고, 각자 다른 랜덤 출발점에 배치합니다.
4. **인게임 플레이**: 장애물을 피해 코인을 모으며 종점으로 이동합니다.
5. **사망 및 재시작**: 한 명이 죽으면 3번 단계로 돌아갑니다 (`시도 횟수 +1`).
6. **클리어**: 두 명 모두 종점에 도착하면 클리어됩니다. 점수·시간·시도 횟수가 기록되고 랭킹이 갱신됩니다.
7. **종료**: 결과 화면 확인 후 로비로 돌아갑니다.

## 📜 3. 게임 규칙 및 판정

### 🗺️ 맵 타일 구조
맵은 격자(칸) 기반이며, 각 칸은 아래 항목 중 하나로 구성됩니다. 판정은 서버가 이 칸 정보로 수행합니다.

| 칸 표시 | 이름 | 설명 |
| :---: | :--- | :--- |
| `.` | **빈칸** | 지나갈 수 있음 |
| `#` | **벽** | 못 들어감 (이동 거부) |
| `X` | **장애물** | 닿으면 사망 |
| `C` | **코인** | 획득 후 사라짐 |
| `G` | **종점** | 도착 (두 명 다 있어야 클리어) |
| `S` | **출발점 후보** | 게임 중에는 빈칸과 동일 |

### 🕹️ 이동 및 판정 규칙
* **조작**: `WASD` 입력 한 번당 한 칸 이동 (`W`: 위, `S`: 아래, `A`: 왼쪽, `D`: 오른쪽).
* **서버 동기화**: 클라이언트는 방향만 전달하고, 새 위치는 서버가 계산하여 두 명에게 전송합니다.
* **이동 제약**: 벽이나 맵 밖으로 이동할 수 없으며, 두 명이 같은 칸에 존재하는 것은 허용됩니다.
* **서버 판정 순서**: `벽 확인` ➔ `장애물 (사망)` ➔ `코인 (획득)` ➔ `종점 (도착)`

### 🪙 코인
* 코인 칸에 들어간 플레이어가 코인을 획득하며, 획득 시 두 명의 화면 모두에서 제거됩니다.
* 개인 점수는 본인이 먹은 코인, 팀 점수는 두 명의 합산입니다. (코인 점수는 `item_types.score`를 따름)
* 두 명이 동시에 같은 코인으로 진입 시, **서버가 먼저 처리한 이동만 획득**으로 판정합니다.

### 💀 사망과 재시작
한 명이라도 장애물에 닿으면 서버는 다음 조치를 한 번에 처리합니다:
1. 사망한 사람의 사망 횟수 +1 (동시 사망 시 둘 다 +1)
2. 시도 횟수 +1 (동시 사망해도 시도 횟수는 +1)
3. 이번 시도에서 모은 코인을 두 명 모두 0으로 초기화 및 맵의 코인 전체 다시 배치
4. 두 명을 출발점 후보 중 서로 다른 칸에 다시 랜덤 배치 후 알림 전송
5. **클리어 시간은 재시작해도 리셋되지 않고 판 시작 순간부터 지속 계산**됩니다.

### 🏁 클리어 및 랭킹
* 먼저 종점에 도착한 플레이어는 이동 입력이 무시되며 대기 상태가 됩니다. 두 번째 플레이어가 도착하는 순간 클리어 처리됩니다.
* 사망과 도착이 같은 순간에 겹치면 **사망이 우선** 적용됩니다.
* **랭킹 정렬 기준**:
  1. 팀 점수 높은 순
  2. 클리어 시간 짧은 순
  3. 시도 횟수 적은 순

## 🖥️ 4. 클라이언트 화면 흐름

| 화면 | 플레이어가 하는 일 | 서버 대답 | 다음 화면 |
| :--- | :--- | :--- | :--- |
| **닉네임** | 닉네임 입력 (2~12자) | 접속 중인 사람과 안 겹치면 등록, 겹치면 거절 | 로비 |
| **로비** | 방 만들기 또는 입장 코드 입력, 랭킹 보기 | 방 생성 시 입장 코드 발급, 입장 성공/실패 이유 | 대기실 |
| **대기실** | 방장은 코드 공유, 나가기 가능 | 두 번째 사람이 들어오면 게임 시작 | 인게임 |
| **인게임** | `WASD` 이동 | 이동 결과, 코인 획득, 사망/재시작, 클리어 알림 | 결과 / 로비 |
| **결과** | 팀 점수, 클리어 시간, 시도 횟수, 순위 확인 | 랭킹 갱신 결과 | 로비 |
| **상대 이탈** | 게임 중 상대가 나가면 안내 표시 | 판 종료 (`ABANDON` 기록) | 로비 |

> **참고사항**: 
> * 인게임에서 사망 시 결과 화면으로 가지 않고 인게임 안에서 즉시 둘 다 재시작합니다.
> * 상대방 이탈 시 상대 이탈 안내 표시 후 로비로 이동합니다.
> * 닉네임은 이번 접속 동안만 유지되며, 재접속 시 새로 정합니다.

## ⚙️ 5. 서버 역할 및 영역 분담

클라이언트 조작을 통한 위치/점수 조작을 방지하기 위해 **모든 판정은 서버가 전담**합니다.

| 영역 | 서버가 하는 일 | 데이터 위치 |
| :--- | :--- | :--- |
| **유저** | 닉네임 검사 및 중복 확인, 플레이어 ID 발급, 접속 시각 기록 | 메모리 (닉네임 목록) + DB (`players`) |
| **방** | 6자리 입장 코드 생성 (중복 방지), 입장 허용/거절, 빈 방 삭제 | 메모리 |
| **게임 시작**| 스테이지 맵 불러오기, 출발점 2개 랜덤 선택, 정보 전송 | DB (`stages`) ➔ 메모리 |
| **이동 처리** | 방향 입력 수신, 시퀀스 번호 검증 (중복/역순 버림), 벽 확인 | 메모리 |
| **충돌 판정** | 장애물 ➔ 코인 ➔ 종점 순으로 판정 | 메모리 |
| **위치 동기화**| 초당 30번 두 명의 위치를 묶어서 전송 (UDP) | 메모리 |
| **사망/리스폰**| 사망/시도 횟수 증가, 코인 재배치, 위치 재배치 | 메모리 |
| **클리어/점수**| 두 명 도착 확인, 점수·시간 계산, 결과 저장 및 순위 조회 | 메모리 ➔ DB (`matches`, `match_results`, `item_pickups`) |
| **이탈 처리** | 연결 끊김 시 판을 `ABANDON`으로 기록 및 상대 알림 | 메모리 ➔ DB (`matches`) |

## 📡 6. 통신 규약 (Network Protocol)

* **TCP**: 신뢰성이 중요한 데이터 (입장, 코인, 사망, 클리어 등) ➔ `[본문 길이 4바이트][JSON 본문]`
* **UDP**: 빈도가 높고 유실되어도 무방한 데이터 (이동 입력, 위치 동기화)

### TCP 패킷 목록
| Type | 방향 | 패킷 이름 | 내용 |
| :---: | :---: | :--- | :--- |
| **1** | 클라 ➔ 서버 | `NICKNAME_REQ` | `nickname` |
| **2** | 서버 ➔ 클라 | `NICKNAME_OK` | `playerId` |
| **3** | 서버 ➔ 클라 | `NICKNAME_FAIL` | `reason`: DUPLICATE / INVALID |
| **10** | 클라 ➔ 서버 | `ROOM_CREATE` | `stageId` |
| **11** | 서버 ➔ 클라 | `ROOM_CREATED` | `roomCode` |
| **12** | 클라 ➔ 서버 | `ROOM_JOIN` | `roomCode` |
| **13** | 서버 ➔ 클라 | `ROOM_JOINED` | `roomCode`, 방 안의 닉네임 목록 |
| **14** | 서버 ➔ 클라 | `ROOM_JOIN_FAIL` | `reason`: NOT_FOUND / FULL / PLAYING |
| **15** | 클라 ➔ 서버 | `ROOM_LEAVE` | — |
| **20** | 서버 ➔ 클라 | `GAME_START` | `matchId`, 맵 데이터, 두 명 시작 위치, `attempt` |
| **21** | 서버 ➔ 클라 | `COIN_PICKED` | `playerId`, `x`, `y`, `teamScore` |
| **22** | 서버 ➔ 클라 | `PLAYER_DIED` | 죽은 `playerId` 목록, `attempt`, 새 시작 위치 |
| **23** | 서버 ➔ 클라 | `PLAYER_ARRIVED` | `playerId` (종점 도착, 대기 중) |
| **24** | 서버 ➔ 클라 | `STAGE_CLEAR` | `teamScore`, `clearTimeMs`, `attempts`, 순위 |
| **25** | 서버 ➔ 클라 | `PARTNER_LEFT` | — (판 종료) |
| **30** | 클라 ➔ 서버 | `RANKING_REQ` | `stageId` |
| **31** | 서버 ➔ 클라 | `RANKING` | 상위 10팀 (두 닉네임, 점수, 시간, 시도 횟수) |

### UDP 패킷 형식
* **클라이언트 ➔ 서버**: `MOVE|playerId|seq|dir`  
  *(예: `MOVE|3|152|W`)*
* **서버 ➔ 클라이언트**: `STATE|tick|id,x,y|id,x,y`  
  *(예: `STATE|880|3,4,7|4,10,2`)*

## 🗄️ 7. 데이터베이스 설계 (DB System)

### 테이블 요약
| 테이블명 | 한 행의 의미 | 주요 컬럼 |
| :--- | :--- | :--- |
| `players` | 접속 기록 (1회성 접속) | `id`, `nickname`, `ip`, `joined_at`, `left_at` (NULL = 접속 중) |

## ⚠️ 8. 예외 상황 처리 정책

| 예외 상황 | 서버 처리 방식 |
| :--- | :--- |
| **접속 중인 닉네임 중복** | `NICKNAME_FAIL (DUPLICATE)`, 다시 입력 유도 |
| **닉네임 길이/문자 오류** | `NICKNAME_FAIL (INVALID)`, 2~12자 유효성 검사 |
| **존재하지 않는 입장 코드** | `ROOM_JOIN_FAIL (NOT_FOUND)` |
| **이미 2명인 방** | `ROOM_JOIN_FAIL (FULL)` |
| **게임 진행 중인 방** | `ROOM_JOIN_FAIL (PLAYING)` |
| **방 코드 중복 발급** | 생성 단계에서 다시 생성 (6자리 영문·숫자, `0`·`O`·`1`·`I` 제외) |
| **대기실에서 방장 이탈** | 방 삭제 처리 후 남은 인원 로비로 이동 |
| **게임 중 한 명 이탈** | 판 종료, DB에 `status = ABANDON` 저장, 남은 사람에게 `PARTNER_LEFT` 전송 |
| **두 명 동시에 사망** | 재시작 1회, 시도 횟수 +1, 두 명 모두 사망 횟수 +1 |
| **사망과 종점 도착 동시 발생**| **사망 우선** (판정 순서: 벽 ➔ 장애물 ➔ 코인 ➔ 종점) |
| **두 명이 같은 코인 동시 진입**| 서버가 먼저 처리한 이동만 코인 획득 인정 |
| **순서가 뒤바뀐 UDP 이동 입력**| `seq <= 마지막 적용 번호`인 패킷은 즉시 버림 |
| **타 주소에서 온 UDP 패킷** | 사칭 방지를 위해 즉시 버림 |
| **형식이 깨진 TCP 패킷** | 해당 패킷만 버리고 경고 로그 기록 후 연결 유지 |
| **클라이언트 위치/점수 변조**| 서버 독립 판정으로 무력화 |
| **서버 비정상 종료 후 재시작** | `left_at`이 빈 `players` 및 끝나지 않은 `matches` 행 정리 (`ABANDON` 처리) |
